# Практическая работа. Вариант №19
## Инструмент визуализации графа зависимостей Cargo

### 1. Цель работы

Целью практической работы являлась разработка инструмента для получения, анализа и визуализации графа зависимостей пакетов менеджера Cargo. Программа должна определять прямые и транзитивные зависимости выбранного пакета, учитывать заданные ограничения анализа и предоставлять возможность исследовать связи между пакетами.

Для получения информации о зависимостях не использовались готовые менеджеры пакетов или специализированные библиотеки. Запросы к репозиторию crates.io выполняются непосредственно из программы.

### 2. Выполненная работа

В ходе работы была разработана консольная программа на языке Python. Реализация разделена на несколько модулей, каждый из которых отвечает за отдельную часть обработки данных.

#### 2.1. Разработка конфигурации приложения

Для настройки программы создан файл `config.xml`. В нём задаются параметры анализа:

- `package_name` — имя пакета, для которого строится граф зависимостей;
- `repository_url` — адрес API репозитория crates.io;
- `test_repository_path` — путь к файлу с тестовым графом зависимостей;
- `test_mode` — переключатель режима работы с тестовым репозиторием;
- `package_version` — версия анализируемого пакета;
- `output_file` — путь и имя выходного файла визуализации;
- `max_depth` — максимальная глубина анализа;
- `filter_substring` — подстрока, по которой исключаются пакеты из анализа.

При запуске приложение считывает XML-конфигурацию и использует её параметры при выполнении дальнейших операций.

#### 2.2. Получение данных о зависимостях

Для получения сведений о пакетах Cargo реализован модуль `dependency_service.py`.

В режиме работы с реальным репозиторием программа обращается к API crates.io с помощью стандартных средств Python. Полученные данные обрабатываются внутри приложения: из ответа извлекаются сведения о прямых зависимостях пакета. Для дальнейшего построения графа также запрашиваются сведения о зависимостях найденных пакетов.

Кроме реального режима предусмотрен тестовый режим. В нём исходные данные загружаются из JSON-файла `examples/test_repository.json`. Это позволяет проверять алгоритм построения графа на заранее подготовленной структуре без обращения к внешнему репозиторию.

#### 2.3. Построение графа зависимостей

В модуле `graph_service.py` реализовано построение графа зависимостей с использованием обхода в ширину (BFS) и рекурсивной обработки найденных пакетов.

При построении графа программа:
- начинает анализ с выбранного корневого пакета;
- получает прямые зависимости текущего пакета;
- последовательно добавляет найденные пакеты и их связи в граф;
- учитывает максимальную глубину анализа из конфигурации;
- исключает пакеты, имена которых содержат заданную фильтрующую подстроку;
- использует множество `visited`, чтобы повторно не обрабатывать уже посещённые пакеты и корректно обрабатывать циклические зависимости.

Корневой пакет имеет глубину 0. Если достигнута установленная максимальная глубина, пакет включается в граф, но его собственные зависимости далее не раскрываются.

Также реализован поиск обратных зависимостей — пакетов, которые прямо или через цепочку связей зависят от указанного пакета. Для этого используется обход графа.

#### 2.4. Визуализация результата

В модуле `visualization_service.py` реализовано формирование текстового описания графа в синтаксисе Mermaid. На основе этого описания с помощью Mermaid CLI создаётся файл изображения графа в формате SVG.

Таким образом, результат анализа можно не только просмотреть в виде структуры связей, но и открыть как отдельную диаграмму.

### 3. Структура проекта

- `main.py` — точка входа в программу. Загружает и проверяет конфигурацию, запускает получение данных, построение графа и его визуализацию.
- `dependency_service.py` — отвечает за получение информации о зависимостях пакетов через API crates.io.
- `graph_service.py` — загружает тестовый граф, строит граф зависимостей, учитывает ограничения анализа и выполняет поиск обратных зависимостей.
- `visualization_service.py` — формирует описание графа и запускает создание SVG-диаграммы.
- `config.xml` — содержит пользовательские настройки программы.
- `examples/test_repository.json` — содержит тестовый граф зависимостей для проверки алгоритма.
- `output/` — каталог для сохранения сформированных файлов визуализации.

### 4. Проверка работы программы

Для проверки алгоритма был подготовлен тестовый репозиторий со следующими связями:

- пакет A зависит от B и C;
- пакет B зависит от D;
- пакет C зависит от D и E;
- пакет D зависит от A;
- пакет E зависит от F;
- пакет F не имеет зависимостей.

Данный пример позволяет проверить несколько ситуаций: наличие общих зависимостей, транзитивные связи, достижение ограничения глубины и циклическую зависимость между пакетами A и D.

Дополнительно предусмотрена проверка фильтрации пакетов по подстроке и поиск обратных зависимостей. Для проверки работы с реальными данными используется API crates.io.

### 5. Используемые технологии

- **Python** — реализация логики приложения.
- **XML** — хранение конфигурационных параметров.
- **JSON** — формат тестового описания графа зависимостей.
- **crates.io API** — источник информации о пакетах Cargo.
- **Mermaid** — текстовое описание графа.
- **Mermaid CLI** — генерация SVG-файла диаграммы.

Для HTTP-запросов и обработки данных на стороне Python используются стандартные средства языка. Для формирования изображения диаграммы требуется установленный Mermaid CLI.

### 6. Результат работы

В результате практической работы разработано CLI-приложение, которое получает сведения о зависимостях пакетов Cargo из crates.io либо из тестового JSON-файла, строит граф прямых и транзитивных зависимостей, учитывает максимальную глубину и фильтрацию, обрабатывает циклические связи и позволяет находить обратные зависимости.

Сформированный граф преобразуется в диаграмму и сохраняется в SVG-файл. Разделение программы на отдельные модули позволяет независимо работать с получением данных, построением графа и визуализацией результата.

---

**Примечание.** В текущей реализации текстовое описание диаграммы формируется на языке Mermaid, а не PlantUML. Автоматизированные тесты в представленном проекте отдельно не добавлены; проверка выполняется на подготовленном тестовом графе и при обращении к реальному API.
